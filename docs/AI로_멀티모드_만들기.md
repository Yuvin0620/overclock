# AI(Claude)로 웹 게임에 멀티 모드 붙이기 — 간단 정리

CLUB OVERCLOCK(three.js + WebXR, Netlify 배포)에 대결 모드를 붙인 흐름을 다른 프로젝트에도 쓸 수 있게 요약.

---

## 1. AI에게 먼저 물어볼 것

- "지금 구조(정적 사이트, Netlify)로 실시간 멀티가 되나?" → 안 됨. 정적 호스팅은 계속 연결을 유지하지 못함.
- "서버 없이 할 수 있는 방법?" → **PeerJS(WebRTC P2P)**: 브라우저끼리 직접 연결. 처음 서로 찾을 때만 무료 공용 서버 사용.
- 규칙도 같이 정하기: 누가 몇 명, 승패 조건, 제한 시간.

## 2. 구조 정하기 (AI에게 이렇게 요청)

- **한 명(방장)이 '진짜' 게임 상태를 갖고**, 나머지는 자기 상태만 보낸다.
- 보내는 데이터는 최소한으로: 위치, 동작, 중요한 이벤트 정도. (초당 5~10번)
- 메시지 종류를 표로 정리해 달라고 하기: `hello` / `start` / 상태 / 이벤트 / `end`.

## 3. 만드는 순서

1. **1:1부터**: 방 만들기 → 코드 입력 → 연결 → 시작 → 결판까지 한 판이 도는 것.
2. **테스트**: 브라우저 탭 2~3개로 직접 연결해 보기 (AI가 탭을 열고 확인까지 해 줌).
3. **인원 확장**: 1 vs 다수, 중간에 나가는 경우 처리.
4. **매칭**: 코드 입력 → 빠른 참가 / 대기열 / 비공개 방.
5. **연결 안정화**: 자동 재접속, 재시도, 학교 와이파이용 **TURN 중계 서버**(Metered 무료).
6. **밸런스**: 직접 플레이해 보고 "이게 너무 쉽다/어렵다"를 AI에게 말하면 해결책을 제안받고 고르기.

## 4. 배포

- 비밀번호(TURN 키)는 코드에 넣지 말고 **Netlify 환경 변수 + Netlify 함수**로.
- 함수까지 올리려면 드래그앤드롭 대신 **GitHub 연동** (GitHub Desktop: Commit → Push → 자동 배포).
- Netlify 무료 플랜은 비공개 저장소에 기여자 1명 제한 → 웹 게임이면 **저장소 공개**가 간단.

## 5. AI와 일할 때 팁

- **한 번에 하나씩** 요청하고, 될 때마다 실제 기기(PC·Quest)에서 확인.
- 안 되면 **증상을 그대로** 말하기: "코드가 없다고 뜸", "연결 중만 뜨다 실패", 화면 캡처.
- 원인을 모를 땐 **진단 표시**(숫자·버전 번호)를 화면에 띄워 달라고 해서 그 값을 알려 주기.
- 수정마다 **백업**과 **문법 검사**를 하게 하기.
- 결정이 필요한 건 AI가 선택지를 주면 고르기 (예: 공개/비공개, 소집 횟수, 판정 시간).
