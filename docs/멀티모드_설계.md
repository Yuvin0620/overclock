# CLUB OVERCLOCK — 대결(멀티) 모드 설계

> 감시로봇 1명 vs 인간 최대 4명이 같은 클럽에서 대결하는 온라인 모드.
> 게임 서버 없이 정적 호스팅(Netlify) 위에서 동작하며, PC 브라우저와 Meta Quest(WebXR) 모두 지원.

---

## 1. 게임 규칙

| 역할 | 목표 | 패배 조건 |
|---|---|---|
| **감시로봇** (1명) | 손님 중 진짜 인간 플레이어를 **전부** 귀가 조치 | 로봇을 3번 잘못 떨어뜨림(민원 3건) |
| **인간** (최대 4명) | 150초 동안 들키지 않기 | 감시로봇에게 귀가 조치 / 의심 100%로 클럽 AI에 적발 |

- 감시로봇 도구: 스캔 3회, **플로어 소집 2회**(노란 레버 → 전원 댄스플로어로).
- 인간 행동(이동·춤 정확도·땀·얼굴에 손·재채기)은 감시 화면의 해당 손님에게 그대로 보인다.
- 감시로봇이 인간을 선택하면 인간 화면에 감시 테두리(실수 시 의심 2배), 스캔하면 경고가 뜬다.

---

## 2. 기술 구성

| 구성 요소 | 사용 기술 | 역할 |
|---|---|---|
| 게임 | three.js + WebXR, `index.html` 한 파일 | 렌더링, 게임 로직 |
| 통신 | **PeerJS (WebRTC P2P)** | 브라우저끼리 직접 연결. 처음 서로 찾을 때만 PeerJS 공용 서버(시그널링) 사용 |
| 중계 | **Metered TURN** | 학교·회사 와이파이처럼 P2P 직접 연결이 막힌 곳에서 데이터 중계 |
| 비밀 정보 | **Netlify 환경 변수 + Netlify Functions** | TURN 아이디/비번을 코드에 두지 않고 `/.netlify/functions/turn`이 내려 줌 |
| 배포 | **GitHub → Netlify 자동 배포** | GitHub Desktop에서 Commit → Push 하면 함수까지 배포 |

## 3. 구조

감시로봇이 방장이고, **감시로봇 쪽 클럽이 정답(authoritative)** 이다. 인간들은 감시로봇에게 접속하는 별(star) 구조.

```
          [감시로봇 = 방장]                     [인간 1~4명]
  ┌───────────────────────────┐        ┌──────────────────────────┐
  │ 진짜 클럽 시뮬레이션          │ ◀───── │ 내 상태만 보냄 (초당 8회)   │
  │ · 평범한 로봇 손님 13명       │  'h'   │  자리(바/플로어), 춤 중?,  │
  │ · 인간마다 아바타 1명         │        │  박자 정확도, 땀, 얼굴에 손, │
  │   (받은 상태로 움직임)        │  'ev'  │  의심 % / 재채기·땀 뚝뚝   │
  │                              │ ─────▶ │                          │
  │ 감시 신호 (초당 5회)          │  's'   │ 선택당함 → 감시 테두리      │
  │ 소집 · 결판 알림              │ 'end'  │ 스캔당함 → 경고            │
  └───────────────────────────┘        └──────────────────────────┘
```

- 동기화하는 건 **인간 플레이어 자신의 상태뿐**이라 데이터가 매우 작다. 인간 화면 속 다른 로봇들은 각자 화면용.
- 감시 화면의 아바타 표현:
  - 바 ↔ 플로어 이동 → 걸어감
  - 박자 정확도 70% 미만 → 흐느적 춤
  - 땀 게이지 높음 → 땀방울 / 얼굴에 손 → 팔 올림 / 재채기 실패 → "에취!"
  - 의심 40% 이상 → 머리 위가 붉게, 65% 이상 → 근처 로봇들이 쳐다봄

### 메시지

| 방향 | 타입 | 내용 |
|---|---|---|
| 방장 → 인간 | `hello` | 접속 승인 + 인간 번호 |
| 방장 → 인간 | `q` | 대기실 상황 (참가 인원, 카운트다운) |
| 방장 → 인간 | `start` | 게임 시작 + 내 자리(바 의자, 플로어 위치) |
| 인간 → 방장 | `h` | 내 상태 |
| 인간 → 방장 | `ev` | 순간 이벤트 (`sneeze`, `drip`) |
| 방장 → 인간 | `s` | 지금 나를 선택/스캔 중인지 |
| 방장 → 인간 | `rally` | 플로어 소집 |
| 양쪽 | `end` | 결판 (승자, 이유) |
| 방장 → 인간 | `full` | 방이 꽉 참 / 이미 시작함 |

## 4. 매칭

메인 화면(AR 로비)에서 **파란 디스크(대결 모드)** 를 본체 드라이브에 넣고 키보드 1·2·3으로 선택.

| 메뉴 | 동작 |
|---|---|
| `[1]` 감시로봇 → `[1]` **공개 대기열** | 방이 자동으로 열림. 인간이 들어온 뒤 15초 동안 새로 아무도 안 오면 자동 시작(누가 오면 다시 15초), 4명이면 즉시 |
| `[1]` 감시로봇 → `[2]` **비공개 방** | 모니터에 3자리 코드 표시. 코드로만 입장. 방장이 `[1]`로 시작 |
| `[2]` **인간 대기열** | 감시로봇이 기다리는 방을 자동으로 찾아 입장. 없으면 「감시로봇 대기 중인 방 없음」 표시 후 계속 탐색 |
| `[3]` **코드로 참가** | 3자리 코드 입력 (비공개 → 공개 방 순으로 찾음) |
| 주황 **ESC** | 뒤로 가기 (대기 취소 / 디스크 빼기) |

- PeerJS 공용 서버는 방 목록을 제공하지 않으므로, 방 번호를 27개(`111`~`333`)로 고정했다.
  - 공개 방: 비어 있는 앞 번호부터 차지 → 인간 대기열은 앞 번호부터 3개씩 차례로 확인.
  - 비공개 방: 별도 주소 공간 + 무작위 번호라 대기열에 잡히지 않음.
- 방장은 시그널링 서버와 끊기면 같은 번호로 자동 재접속한다.

## 5. 밸런스 설계

원칙: **위치로는 못 찾고, 행동을 보고 찾게.**

| 장치 | 내용 |
|---|---|
| 무작위 자리 | 인간 시작 자리를 바 의자 5개 · 플로어 자리 중 무작위 배정 |
| 평범한 로봇만 | 대결에선 가발·녹·냉각수·테이프 같은 헷갈리는 장식 로봇 없음 |
| 바 의자 꽉 채움 | 인간 자리 외 바 의자는 전부 로봇. 3.5~7초마다 로봇들이 바↔플로어 자리 교대 |
| 직접 이동 | 인간이 바↔플로어를 자유롭게 오감 (표지판 · PC `M` 키 · Quest A/X 버튼) |
| 플로어 소집 | 감시로봇 2회. 로봇은 칼박, 인간은 끌려가서 24박 춤. 도중에 빠지면 의심 +10 |
| 판정 강화 | 대결 모드 플로어 춤: 완벽 0.075초 · 좋아 0.135초 (1인 모드 0.11 · 0.2초) |
| 의심 단서 | 인간 의심 40%↑ 머리 위 붉게, 65%↑ 근처 로봇이 쳐다봄 |

## 6. TURN 중계 설정

1. Metered에서 TURN credential 발급 (무료 월 500MB).
2. Netlify → Environment variables에 `TURN_USER`, `TURN_PASS` 등록 (secret 체크).
3. `netlify/functions/turn.mjs`가 환경 변수를 읽어 중계 서버 목록을 반환.
4. 게임은 연결 직전에 이 함수를 호출해 STUN + TURN 목록으로 연결. 함수가 없으면 STUN만으로 직접 연결 시도.
